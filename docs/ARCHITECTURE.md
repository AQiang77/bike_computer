# Bike Computer 固件架构

## 目标

固件支持三种运行模式，并共享骑行数据采集、记录、蓝牙和界面能力：

1. 离线记录：设备使用 GPS 和运动传感器记录骑行。
2. 路书导航：设备读取已导入的路书，同时记录骑行。
3. 手机导航：手机下发导航指令，设备负责显示并可上传实时数据。

当前阶段只建立可编译的软件边界。GPS、运动传感器、文件系统、BLE 和路书
算法尚未启用，相关接口返回 `-RT_ENOSYS`。

## 依赖方向

```text
main -> app -> modes -> core/services -> RT-Thread/SiFli SDK drivers
                    \-> route
                    \-> protocol
app -> ui -> LVGL
```

- `main.c` 只负责进入应用。
- `app` 管理系统启动和模式选择。
- `modes` 只编排业务，不直接访问 LVGL 或硬件驱动。
- `core` 保存公共数据类型、骑行状态和统一导航数据。
- `services` 封装 RT-Thread 设备及硬件驱动。
- `route` 保存设备路书格式以及后续路线匹配接口。
- `protocol` 保存手机与设备共享的 BLE 协议定义。
- `ui` 只接收公共模型并在 GUI 线程中调用 LVGL。

## 数据约定

- 设备内部坐标统一为 WGS-84。
- 经纬度以度乘以 `10^7` 的有符号整数保存。
- 海拔单位为分米，速度单位为厘米每秒，航向单位为百分之一度。
- 未实现的服务不得输出成功状态，也不得在系统启动时访问硬件。
